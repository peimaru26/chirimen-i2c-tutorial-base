# SGP30 の値の読み方とメソッド解説

実機（Raspberry Pi Zero / M5Stack U088 / シリアル `000001f9293c`）で取得したデータを使って、
4つの測定値と各メソッドの意味をまとめる。

出典: [SGP30 データシート Version 1.0 (May 2020)](https://sensirion.com/media/documents/984E0DD5/61644B8B/Sensirion_Gas_Sensors_Datasheet_SGP30.pdf)

---

## 4つの値の一覧

| 値        | 意味                           | 単位               | 範囲        | 上がると                 |
| --------- | ------------------------------ | ------------------ | ----------- | ------------------------ |
| `eCO2`    | CO2 相当値（equivalent CO2）   | ppm                | 400 - 60000 | 空気が汚れた             |
| `tvoc`    | 総揮発性有機化合物             | ppb                | 0 - 60000   | 空気が汚れた             |
| `h2`      | 水素センサー素子の生信号       | ティック（無次元） | -           | **空気がきれいになった** |
| `ethanol` | エタノールセンサー素子の生信号 | ティック（無次元） | -           | **空気がきれいになった** |

**生信号は方向が逆**である点が最大の注意点。詳細は後述。

---

## eCO2（CO2 相当値）

### 何を表すか

単位は ppm、下限は **400 ppm**。屋外の清浄な空気の CO2 濃度が約 400 ppm なので、これが「きれいな空気」の
基準値になっている。値が上がるほど空気が汚れている（＝人がいる、換気が足りない）ことを意味する。

一般的な目安:

| eCO2            | 状態                                                     |
| --------------- | -------------------------------------------------------- |
| 400 ppm         | 基準値（清浄）。初期化フェーズ中の固定値でもあるので注意 |
| 400 - 1000 ppm  | 通常の室内                                               |
| 1000 - 2000 ppm | 換気が不足しはじめている                                 |
| 2000 ppm 以上   | 明確に換気が必要                                         |

### 重要: 本物の CO2 濃度ではない

名前が "equivalent"（相当値）である理由がここにある。

SGP30 は **MOX（金属酸化物半導体）方式**のセンサーで、加熱した金属酸化膜の抵抗が還元性ガスによって
変化することを利用している。**CO2 は化学的に非常に安定で還元性を持たないため、この方式では検出できない。**

つまり SGP30 は CO2 を測っていない。室内では人の呼吸や活動によって CO2 と他のガス（水素など）が
一緒に増えるという経験的な相関を利用して、検出できたガスから CO2 濃度を**推定**している。

この帰結として:

- 人がいる室内の換気状態を見る用途には有効
- ドライアイスや CO2 ボンベのように**「CO2 だけ」を増やしても反応しない**
- 逆にアルコールを近づけると、CO2 は増えていないのに eCO2 が跳ね上がる

用途を誤解しないことが重要。CO2 濃度そのものを測りたい場合は SCD40 のような NDIR 方式（赤外線吸収）の
センサーを使う。

## TVOC（総揮発性有機化合物）

単位は ppb（10億分率、ppm の1000分の1）、下限は **0 ppb**。
アルコール、溶剤、香料、接着剤、建材から出るガス、体臭などの揮発性有機化合物の総量を表す。

「総量」なので、**どの物質がどれだけあるかは分からない**。エタノール換算の総和として出てくる。

| TVOC          | 状態     |
| ------------- | -------- |
| 0 - 220 ppb   | 良好     |
| 220 - 660 ppb | 許容範囲 |
| 660 ppb 以上  | 換気推奨 |

アルコール系のウェットティッシュや消毒液を近づけると数千 ppb まで一気に跳ね上がり、
戻るのに数分かかる。動作確認に使いやすい反面、一度上げると当分下がらない。

## raw H2 / raw Ethanol（生信号）

### 何を表すか

SGP30 の中には複数のセンサー素子があり、そのうち2つの生の出力がこれ。
`eCO2` / `tvoc` は、この生信号をセンサー内部のアルゴリズムが加工した**計算結果**である。
生信号はその加工前の値。

単位は「ティック」で、物理的な単位を持たない。**素子の抵抗値を対数スケールに変換した値**。

### 値の向きが逆になる理由

データシートに濃度への換算式がある。

```
c = cref × exp((sref - sout) / 512)
```

| 記号   | 意味                                        |
| ------ | ------------------------------------------- |
| `c`    | 求めたいガス濃度                            |
| `cref` | 基準濃度（エタノール 0.4 ppm / H2 0.5 ppm） |
| `sref` | 基準濃度のときの生信号値                    |
| `sout` | 実際に読んだ生信号値                        |

指数の分子が `sref - sout` なので、**`sout` が小さくなるほど濃度 `c` は大きくなる**。
ガス濃度が上がると素子の抵抗が下がり、生信号の数値も下がる。

つまり:

- **raw の数値が下がった → ガス濃度が上がった（空気が汚れた）**
- **raw の数値が上がった → ガス濃度が下がった（空気がきれいになった）**

`eCO2` / `tvoc` とは動きが逆になる。

### ティックの換算早見表

対数スケールなので、ティックの差がそのまま濃度の**倍率**になる。

| ティックの差  | 濃度の変化          |
| ------------- | ------------------- |
| 1 ティック    | 約 0.196%           |
| 355 ティック  | 2 倍                |
| 512 ティック  | e 倍（約 2.718 倍） |
| 1024 ティック | e² 倍（約 7.39 倍） |

2点間の**濃度比は `sref` を知らなくても計算できる**（式から `cref` と `sref` が消えるため）。

```
c2 / c1 = exp((s1 - s2) / 512)
```

## 実測データで検証してみる

息を吹きかけたときのログ（1秒間隔）。上の式で濃度比を計算した。

| eCO2 | TVOC | raw H2 | raw EtOH | H2 濃度比 | EtOH 濃度比 | eCO2 の比 |
| ---: | ---: | -----: | -------: | --------: | ----------: | --------: |
|  400 |    0 |  13429 |    17865 |     1.00x |       1.00x |     1.00x |
|  787 |   92 |  12995 |    17718 |     2.33x |       1.33x |     1.97x |
| 1144 |  185 |  12834 |    17583 |     3.20x |       1.73x |     2.86x |
| 1375 |  243 |  12760 |    17486 |     3.69x |       2.10x |     3.44x |
| 1510 |  330 |  12711 |    17415 |     4.06x |       2.41x |     3.77x |
| 1580 |  402 |  12685 |    17358 |     4.28x |       2.69x |     3.95x |

ピーク時の計算例:

```
H2   : exp((13429 - 12685) / 512) = exp(1.453) = 4.28 倍
EtOH : exp((17865 - 17358) / 512) = exp(0.990) = 2.69 倍
eCO2 : 1580 / 400                             = 3.95 倍
```

### 分かったこと

**`eCO2` の変化倍率が、H2 の濃度比とよく一致している。**
全6行で `1.00 / 1.97 / 2.86 / 3.44 / 3.77 / 3.95`（eCO2）に対して
`1.00 / 2.33 / 3.20 / 3.69 / 4.06 / 4.28`（H2）で、誤差 15% 程度に収まっている。
一方エタノール側は `1.00 / 1.33 / 1.73 / 2.10 / 2.41 / 2.69` で明らかに動きが違う。

これは **`eCO2` が H2 の生信号から計算されている**ことを強く示唆する。

> ただしこれは実測からの推測。データシートは "Based on the sensor signals a total VOC signal (TVOC)
> and a CO2 equivalent signal (CO2eq) are calculated" と述べるだけで、
> **どの生信号がどの出力に対応するかは明記していない。**

また、息には水素（腸内発酵由来）と揮発性有機化合物の両方が含まれるため、
両方の生信号が同時に下がっている。

### 換算式が使えない場面

冷間起動直後のログでは `raw H2 = 8184 → 11367 → 13678` と急上昇していた。
これに換算式をあてはめると、定常値 13460 を基準にして 29872 倍という無意味な値が出る。

これはガス濃度の変化ではなく、**センサー内部のヒーターが温まっている過程**である。
SGP30 は素子を加熱して抵抗変化を見るため、熱平衡に達するまで生信号が動き続ける。
起動直後の生信号に換算式を適用してはいけない。

## メソッドごとの解説

### `read()` → `{ eCO2, tvoc }`

コマンド `0x2008`、待ち 12ms、応答 6 バイト。

**約1秒間隔で呼び続ける必要がある。** データシートの指定で、動的ベースライン補正アルゴリズムが
この周期を前提に動いている。間隔が乱れると補正が正しく働かない。

`init()` 直後の**約15秒間は測定していない**。`400 ppm` / `0 ppb` という固定値を返すだけなので、
この間の値は捨てる。息を吹きかけても動かない。

### `readRaw()` → `{ h2, ethanol }`

コマンド `0x2050`、待ち 25ms、応答 6 バイト。

生信号を取る。**初期化フェーズの15秒に関係なく、最初から本物の測定値が返る**（ただし暖機中）。

使いどころ:

- `eCO2` / `tvoc` はベースライン補正がかかっているため「最近いちばんきれいだった空気からの相対値」で、
  絶対的な空気の状態を表さない。絶対値に近いものが欲しい場合は生信号を使う
- 自分で独自の判定ロジックを組みたい場合
- センサーが生きているかの確認（`eCO2` が固定値の15秒間でも生信号は動く）

`read()` と併用すると、両者が逆方向に動くことで実装の正しさを相互検証できる（上記の実測が実例）。

### `readSerialNumber()` → `"000001f9293c"`

コマンド `0x3682`、待ち 10ms、応答 9 バイト（3ワード = 48bit）。

センサー個体に焼かれている固有 ID。**測定とは無関係で、値そのものに意味はない。**

役割は**疎通確認**。I2C の配線が正しく CRC も合っていれば必ず同じ値が返る。
配線が怪しければ全ゼロや化けた値、あるいは CRC エラーになる。
測定値とは独立に「センサーと正しく喋れているか」を確認できるので、デバッグの切り分けに効く。

今回 `000001f9293c` が安定して返ったことで、I2C 通信と CRC 実装の正しさが確認できた。

### `getBaseline()` → `{ eCO2, tvoc }`

コマンド `0x2015`、待ち 10ms、応答 6 バイト（応答順は **CO2eq → TVOC**）。

**ppm / ppb ではない。** ベースライン補正アルゴリズムの内部状態（不透明な16bit値2つ）。
人間が読んで意味を解釈するものではなく、保存して書き戻すためだけに存在する。

SGP30 は絶対的なガス濃度を測れない。やっているのは
**「最近いちばんきれいだった空気」を基準として覚えておき、そこからのズレを出す**こと。
この基準がベースラインで、学習には最大12時間の連続運転が必要。

### `setBaseline(eCO2, tvoc)`

コマンド `0x201E`、待ち 10ms、パラメータは **TVOC → CO2eq の順**（`getBaseline()` と逆）。

保存しておいたベースラインを書き戻す。**`init()`（= `iaq_init`）の後に呼ぶ必要がある**（データシートの指定）。

なぜ必要かというと、**学習結果は電源を切ると消える**。毎回コンセントを抜くたびに
12時間かけて学習をやり直すことになる。`getBaseline()` の値をファイルに保存し、
次回起動時に `setBaseline()` で復元すれば、学習をやり直さずに済む。

#### パラメータ順の罠

データシートの記述:

- `sgp30_get_iaq_baseline` の応答は "in the order **CO2eq and TVOC**"
- `sgp30_set_iaq_baseline` のパラメータは "in the order as **(TVOC, CO2eq)**"

**読むときと書くときで順番が逆。** 取り違えても I2C 通信としてはエラーにならず、
CRC も通るため、「エラーは出ないのに値がおかしい」という最も見つけにくいバグになる。

このドライバーは引数・返り値をどちらも `eCO2` を先に統一し、電文の入れ替えは内部で吸収している。
`main_baseline.js` の往復テスト（現在値を書き戻して読み直す）がその検証を兼ねている。

## 早見表: 値が動いたときの読み方

| 観測                             | 意味                                                 |
| -------------------------------- | ---------------------------------------------------- |
| `eCO2` が上がった                | 空気が汚れた（人の呼吸・換気不足・アルコール等）     |
| `eCO2` が 400 のまま動かない     | 初期化フェーズ中（起動から15秒）か、本当に清浄       |
| `tvoc` が上がった                | 揮発性有機化合物が増えた（溶剤・香料・アルコール等） |
| `raw H2` が**下がった**          | 水素濃度が上がった＝空気が汚れた                     |
| `raw H2` が**上がった**          | 水素濃度が下がった＝空気がきれいになった             |
| `raw` が起動直後に急上昇している | ヒーターの暖機中。ガスの変化ではない                 |
| `eCO2` と `raw` が同じ方向に動く | **実装がおかしい**（本来は逆相関するはず）           |
| `raw` が全く動かない             | 通信は通っているが素子が死んでいる可能性             |
| CRC エラーが出る                 | 配線の接触不良、ノイズ、プルアップ不足               |

# 追記: エタノール曝露実験からの解析

センサーにエタノールを塗った手をかぶせ、30秒間 1Hz で記録したデータの解析。
`eCO2` が 1837 → 27246 ppm（約15倍）まで振れた大振幅のデータが取れたため、
前節よりはるかに強い検証ができた。

## 1. eCO2 は H2 チャンネルから計算されている（ほぼ確定）

エタノール投入直前（`eCO2` 1837 ppm）を基準にした濃度比。

|  eCO2 |  TVOC | **H2 濃度比** | **eCO2 の比** | EtOH 濃度比 |
| ----: | ----: | ------------: | ------------: | ----------: |
|  3284 |   408 |          1.7x |          1.8x |        1.9x |
|  4734 |  1649 |          2.6x |          2.6x |        5.6x |
|  8284 |  5204 |          4.2x |          4.5x |       16.2x |
| 11707 | 13745 |          6.4x |          6.4x |       41.5x |
| 18217 | 30964 |          9.2x |          9.9x |       78.8x |
| 25095 | 53447 |         13.0x |         13.7x |      151.0x |
| 27246 | 60000 |     **14.9x** |     **14.8x** |      193.2x |

18 点すべてで **`eCO2` の変化倍率と H2 の濃度比が平均誤差 4.3%（最大 8.9%）で一致**する。
エタノール側は 193 倍まで振れており、まったく一致しない。

15 倍のダイナミックレンジにわたってこの精度で一致するため、
**`eCO2` は H2 の生信号から計算されている**と考えてよい。

> データシートは "Based on the sensor signals ... are calculated" とだけ述べ、
> どの生信号がどの出力に対応するかは明記していない。これは実測からの結論。

## 2. 内部の計算式を逆算できた

濃度換算式 `c = cref × exp((sref - sout) / 512)` を出発点に、実測値から係数を求めた。

### eCO2

```
eCO2 [ppm] = 400 × exp((sref_H2 - rawH2) / 512)
```

各行から `sref_H2` を逆算すると、30 行すべてで **13866 - 13939（幅 73 ティック、変動 0.5%）**に収まる。
`sref_H2 = 13910` を採用したときの予測精度:

| rawH2 | 実測 eCO2 | 予測 eCO2 |  誤差 |
| ----: | --------: | --------: | ----: |
| 13115 |      1837 |      1889 | +2.9% |
| 12221 |     10775 |     10831 | +0.5% |
| 11732 |     27246 |     28148 | +3.3% |
| 12335 |      9002 |      8669 | -3.7% |

**平均絶対誤差 3.4%**。前節の「息」のデータでも同じ形が成り立つ（`sref_H2 = 13377`、誤差 3% 程度）。

下限が 400 ppm になる理由もこの式で説明できる。`rawH2 = sref_H2` のとき `exp(0) = 1` なので
`eCO2 = 400`。**ベースラインと同じ空気なら必ず 400 ppm を返す。**

### TVOC

```
TVOC [ppb] = 234 × (exp((sref_E - rawEtOH) / 512) - 1)
```

`sref_E = 19885`、係数 234 で **平均絶対誤差 6.0%**。

| rawEtOH | 実測 TVOC | 予測 TVOC |
| ------: | --------: | --------: |
|   19680 |       125 |       115 |
|   19030 |       973 |      1010 |
|   18254 |      5204 |      5429 |
|   17604 |     20228 |     19921 |
|   17111 |     53447 |     52558 |

**`eCO2` と違って末尾に `- 1` が付く。** これが下限の違いを説明する。

|      | 式の形                 | `raw = sref` のとき | 下限        |
| ---- | ---------------------- | ------------------- | ----------- |
| eCO2 | `400 × exp(...)`       | 400                 | **400 ppm** |
| TVOC | `234 × (exp(...) - 1)` | 0                   | **0 ppb**   |

`eCO2` は「屋外の清浄空気 400 ppm」を基準にした乗算型、
`TVOC` は「汚染ゼロ」を基準にした差分型、という設計の違いがある。

## 3. 2つの生信号は化学的選択性が本当に違う

これが今回いちばん重要な発見。同じセンサーの2つのチャンネルが、
**刺激の種類によって反応の優劣が逆転する**。

| 刺激               | H2 濃度比 | EtOH 濃度比 |                   EtOH / H2 |
| ------------------ | --------: | ----------: | --------------------------: |
| 息を吹きかけた     |     4.28x |       2.69x |         **0.63**（H2 優位） |
| エタノールを塗った |     14.9x |      193.2x | **13.0**（EtOH 圧倒的優位） |

比が 0.63 から 13.0 へ、**約 20 倍の逆転**が起きている。

これは 2 つのチャンネルが単なる冗長な複製ではなく、
**異なる化学的選択性を持つ独立した素子である**ことの直接的な証拠。

- 息には水素（腸内発酵由来）が多く含まれ、H2 チャンネルが強く反応する
- エタノールにはエタノールチャンネルが桁違いに強く反応する

副産物として、**ドライバーの実装が正しいことの強い裏付け**にもなっている。
もし 2 つの生信号を取り違えていたり、バイト順を誤っていたら、
刺激によって優劣が逆転するような整合した振る舞いにはならない。

## 4. TVOC が上限に張り付いた — `readRaw()` の存在価値の実証

23・24 行目で **`TVOC` が 60000 ppb で 2 回連続して止まっている**。
これはデータシートの出力上限（0 - 60000 ppb）に達したためのクリップ。

|        |          TVOC |  eCO2 | rawEtOH |
| ------ | ------------: | ----: | ------: |
| 23行目 | 60000（飽和） | 26970 |   17008 |
| 24行目 | 60000（飽和） | 27246 |   16985 |

**`TVOC` は止まっているのに `eCO2` と生信号は動き続けている。**
上の式でこの2行の TVOC を計算すると 64321 ppb / 67287 ppb になり、
本来はまだ上昇していたことが分かる。

つまり **上限は「センサーの限界」ではなく「出力フォーマットの限界」**。
強い VOC イベントを扱いたい場合は `readRaw()` を使う必要がある。
これは生信号を実装に含めた判断が正しかったことの実証になっている。

## 5. eCO2 を CO2 として読んではいけないことの実証

ピークで **`eCO2` = 27246 ppm** に達した。もしこれが本物の CO2 濃度なら、
40000 ppm 以上で生命に危険が及ぶ領域に近い、極めて異常な数値である。

しかし**この実験で CO2 は1分子も増えていない。** 増えたのはエタノールと、
手をかぶせたことによる水素・水蒸気だけ。

`eCO2` は「還元性ガスの量から CO2 濃度を推定した値」なので、
**CO2 と相関しない汚染源に対しては完全に破綻する。**
「換気の指標」としては使えるが、「CO2 濃度計」としては使えない。

## 6. ベースラインはスパイクに動じなかった

逆算した `sref_H2` が 30 行すべてで幅 73 ティック（0.5%）に収まっていた、という事実は
別の意味も持つ。**`eCO2` が 15 倍に振れている最中も、ベースラインは動いていない。**

動的ベースライン補正は「最近いちばんきれいだった空気」を追跡するので、
汚れた方向へのスパイクでは基準がずれない設計になっている。
今回の大曝露でセンサーの較正を壊した心配はない。

一方、前節（息）のセッションでは `sref_H2 = 13377`、今回は `13910` で **533 ティックの差**がある。
これは倍率にして約 2.8 倍。**セッション間では確かにベースラインが動いている。**
`getBaseline()` / `setBaseline()` が保存・復元しているのは、まさにこの量である。

## 7. 交絡要因: 手で包んだこと

「手で包んだ」操作は、エタノール蒸気を閉じ込めるだけでなく
**温度と湿度も上げている**。MOX センサーは湿度の影響を受けるため、
今回の応答にはエタノール以外の寄与も含まれている。

SGP30 に `Set_humidity`（`0x2061`）という湿度補正コマンドが存在するのは、まさにこのため。
今回は「補正が効いたかを検証できない」という理由で実装を見送ったが、
**この実験は、その機能が存在する理由を実感できる例になっている。**

厳密にエタノールだけの応答を見たい場合は、密閉容器と別途の温湿度センサーが必要になる。

## 8. 注意: 飽和するレベルの曝露を習慣にしない

MOX センサーは高濃度の溶剤蒸気に繰り返し曝露されると特性が変化しうる。
動作確認として時々行うのは問題ないが、毎回 60000 ppb まで振らせる必要はない。
息を吹きかける程度（前節の 4 倍程度の応答）でも検証には十分。

# 追記2: ベースライン値の実測 — 予測は外れた

前節で「ベースラインは生信号のティック値そのままで保存されているのではないか」と予測したが、
**実測で外れたことが確認できた。**

|         | 逆算した基準値 | 実測のベースライン値 |   比 |
| ------- | -------------: | -------------------: | ---: |
| eCO2 側 |          13910 |     38159 (`0x950f`) | 2.74 |
| TVOC 側 |          19885 |     39842 (`0x9ba2`) | 2.00 |

比が 2.74 と 2.00 で一致しないため、単純なスケール変換でもない。
**生信号とは別の内部エンコード**で保持されている。

なお実測値は Adafruit の example にあるコメント値（`0x8E68` = 36456 / `0x8F41` = 36673）と
同じオーダーで、そちらとは整合的だった。

データシートがベースライン値の意味を説明していないのは妥当で、
**保存して書き戻すだけの不透明な値**として扱うのが正しい、という結論になる。

逆算した式（`eCO2 = 400 × exp((sref - rawH2) / 512)`）自体は、
同一セッション内で平均誤差 3.4% という精度で成立している。
`sref` がアルゴリズムの内部状態を反映していることは確かだが、
それが I2C で読み出せるベースライン値と同じ表現とは限らない、ということ。

# 追記3: eCO2 の実測上限は 57330 ppm（データシートは 60000 ppm）

`@chirimen/sgp30` としてリンクした状態での検証中に観測した挙動。

## 観測

エタノール曝露時、**`eCO2` が 57330 ppm で6回連続して固定された。** その間 `rawH2` は
`11668 → 11548` と動き続けている。

|     rawH2 | 実測 eCO2 | `400 × exp((sref − rawH2)/512)` の予測 |
| --------: | --------: | -------------------------------------: |
|     13755 |      1739 |                                   1707 |
| **11668** | **57330** |                                100,590 |
| **11620** | **57330** |                                110,477 |
| **11548** | **57330** |                                127,158 |
|     12009 |     55510 |                                 51,678 |

このセッションの `sref_H2` は 14498（静止時に `eCO2 = 400` を返していた `rawH2` の値）。
張り付いていない区間では式が誤差 ±14% 以内で成立しており、
**57330 はアルゴリズム側の上限**であると判断できる。

## データシートとの食い違い

| 出力 | データシートの上限 |                    実測の上限 |
| ---- | -----------------: | ----------------------------: |
| TVOC |          60000 ppb |   **60000 ppb**（仕様どおり） |
| eCO2 |          60000 ppm | **57330 ppm**（仕様より低い） |

同じチップの2つの出力で上限の扱いが異なる。`57330`（`0xDFF2`）という値の由来は説明できていない。

> **注意**: 1個体・1回の観測である。公式な仕様として扱うべきではない。
> `packages/sgp30/README.md` のスペック欄はデータシートの `400 - 60000 ppm` のまま据え置いている。

## `readRaw()` を実装した判断の裏付け

この区間では **`eCO2` と `TVOC` が両方とも天井に張り付き、生信号だけが動き続けている。**

|         |            値 | 状態       |
| ------- | ------------: | ---------- |
| eCO2    |         57330 | 張り付き   |
| TVOC    |         60000 | 張り付き   |
| rawH2   | 11668 → 11548 | 動いている |
| rawEtOH | 17377 → 16887 | 動いている |

「出力の上限はセンサーの限界ではなく出力フォーマットの限界」という前節の主張が、
**eCO2 側でも確認できた**ことになる。強い曝露を扱う用途では生信号が必要になる。
